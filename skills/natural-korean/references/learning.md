# 로컬 학습 절차

이 문서는 현재 작업에서 지속적인 문체 교정 신호가 확인된 뒤에만 읽는다. 학습은 공개 스킬을 바꾸는 작업이 아니라, 직장 환경에 둔 로컬 취향 상태를 갱신하는 작업이다.

## 학습해도 되는 사건

### 지속 지시

사용자가 `앞으로`, `항상`, `이런 문서에서는`처럼 재사용 범위를 밝히며 문체를 고치거나 삭제하라고 한 경우다. 범위가 명확한 지시는 검토 완료 취향으로 기록할 수 있다.

### 사람이 고친 결과

AI 산출물과 사람이 고친 결과를 현재 작업에서 함께 확인한 경우다. 사실과 양태가 같고 표현만 달라졌을 때 문체 후보로 기록한다. 한 번의 관찰만으로 활성화하지 않는다.

## 학습하지 않을 사건

- `이 문장만`, `이번 장표만`처럼 일회 범위가 명확한 수정
- 사실, 수치, 이름, 일정, 논리, 요구사항이 달라진 수정
- 사람이 고친 전후를 직접 확인하지 못한 추측
- 인용문이나 법령 문구의 변경
- 기존 문서 관례를 따른 결과일 뿐 지속 취향인지 알 수 없는 차이

판단이 애매하면 현재 산출물만 고치고 학습하지 않는다.

## 저장 원칙

- 공개 스킬 디렉터리의 `SKILL.md`, `references`, `scripts`, 테스트를 학습 과정에서 수정하지 않는다.
- 로컬 상태에는 일반화한 규칙과 최소 메타데이터만 저장한다.
- 원문·수정문, 실제 업무 문장, 문서 내용·경로, 프롬프트, 고유명사, 수치, 식별자를 저장하거나 Git 커밋 본문에 넣지 않는다.
- 관찰된 수정은 먼저 `candidate`로 둔다. 명확한 지속 지시나 서로 다른 맥락에서 반복된 사람의 교정만 `active` 프로필과 `rules.local.json`에 반영한다.
- 성능 지표에는 사람이 검토했다고 확인한 산출물과 문체 교정만 포함한다. 후보 수나 단순 생성 횟수로 개선을 주장하지 않는다.

## 상태 디렉터리와 Git

상태 경로는 `profile-schema.md`의 순서로 정한다: 명시적 `--data-dir`, `NATURAL_KOREAN_DATA_DIR`, 호스트가 제공한 `CLAUDE_PLUGIN_DATA/natural-korean`.

`learn.py init`은 이 디렉터리에 상태 파일을 추적하는 로컬 Git 저장소를 준비한다. 상태 루트는 현재 POSIX 사용자가 소유한 `0700`, 그 안의 파일과 Git 객체는 다른 사용자가 읽을 수 없는 권한으로 유지한다. `.git`을 외부 경로로 돌리거나 symlink로 바꿀 수 없다. 이 저장소는 공개 스킬 저장소와 다른 Git 저장소 밖에 따로 두며 remote를 두지 않는다. 학습 명령은 remote가 발견되면 기록을 중단해야 하며 `push`, `pull`, `fetch`를 실행하지 않는다.

데이터 디렉터리가 설정되지 않았거나 현재 환경이 직장용인지 확실하지 않으면 초기화하거나 기록하지 않는다. 규칙 요지만 현재 대화에서 제안하고 사용자가 적절한 환경에서 다시 실행하게 한다.

## 명령 계약

실제 인자는 설치된 스크립트의 도움말을 먼저 확인한다.

```sh
python3 scripts/learn.py --help
python3 scripts/learn.py <command> --help
```

지원하는 하위 명령의 역할:

| 명령 | 역할 |
|---|---|
| `init` | 상태 파일과 remote 없는 로컬 Git 저장소를 생성·검증 |
| `record` | 일반화한 지속 지시나 관찰을 기록. 명시적 지속 지시는 활성화하고 관찰 수정은 후보로 보관 |
| `review` | 사람이 실제로 검토한 산출물의 글자 수·문체 교정·오탐 수를 성능 지표에 기록 |
| `status` | 활성 취향, 대기 후보, 검토 완료 지표, 저장소 안전 상태 확인 |
| `history` | 민감한 전후 문장 없이 학습·검토·철회 이력 확인 |
| `revert` | 지정한 학습 커밋을 되돌리는 새 로컬 커밋을 기록 |

공통 `--data-dir`은 하위 명령 앞에 둔다. `record`에는 일반화한 `--preference`, 출처(`explicit`, `correction`, `observed`), 장르(`all`, `ppt`, `report`, `email`, `code`)를 전달하고 필요할 때만 일반화한 `--avoid`와 `--prefer`를 더한다. `--avoid`는 정규식이 아니라 실제 문서에서 찾을 짧은 리터럴이다. 명시적 지시를 즉시 활성화하려면 재사용 범위가 분명할 때만 `--durable`을 쓴다. 사람의 교정이 서로 다른 맥락에서 두 번째로 확인됐을 때만 두 번째 기록에 `--separate-context`를 쓴다.

`review`는 후보 승인 명령이 아니다. `--human-reviewed`와 글자 수, 문체 교정 수, 검사기 오탐 수가 모두 확인됐을 때만 실행한다. `revert`에는 `history`에서 확인한 16진수 커밋 SHA만 전달한다. 세부 옵션은 각 명령의 `--help`를 따른다.

셸 인자에 원문 전후를 넣지 않는다. 스크립트에 전달하는 문자열은 일반화한 취향과 합성 표현뿐이어야 한다.

## 한 번의 학습 순서

1. **신호 분류:** 지속 지시, 관찰 수정, 일회 수정, 내용 수정 중 하나로 가른다.
2. **의미 대조:** 사실·수치·이름·양태가 같을 때만 문체 신호로 본다.
3. **메모리에서 일반화:** 실제 문장을 복사하지 않고 `어느 장르에서 무엇을 피하고 무엇을 선호하는가`로 요약한다.
4. **기존 상태 확인:** `status`와 현재 `profile.json`을 읽어 중복·충돌·더 좁은 범위의 기존 규칙을 찾는다.
5. **기록:** `record`로 최소 정보만 남긴다.
   - 명확한 지속 지시는 사용자의 그 발화 자체를 근거로 보고 `--durable`로 활성화할 수 있다.
   - 사람의 교정은 candidate로 남긴다. 같은 일반화가 독립된 맥락에서 다시 확인될 때만 두 번째 `record`에 `--separate-context`를 붙여 활성화한다.
6. **검토 지표:** 사람이 실제 산출물을 검토한 뒤에만 `review --human-reviewed`로 글자 수·문체 교정·오탐 수를 기록한다. 미검토 산출물과 자기 평가는 기록하지 않는다.
7. **회귀 확인:** 활성 규칙이 생겼다면 실제 장르를 붙여 `scripts/check.py --genre <장르> --state-dir <상태 디렉터리> <절대 경로>`로 합성 예시와 현재 산출물을 검사한다. 이미 커밋된 규칙이 오탐이면 해당 커밋을 `revert`한 뒤 범위를 좁혀 다시 기록한다.
8. **이력 확인:** `history`로 이번 변경의 로컬 커밋과 remote 부재를 확인한다.

## 자기 성찰

보고서나 PPT를 납품한 사실만으로는 실수를 알 수 없다. 사람이 수정했거나 수정 지시를 한 뒤에만 아래를 검토한다.

- 무엇이 문체 문제였는가
- 장르와 독자 범위는 어디까지인가
- 기존 스타일 가이드로 이미 막을 수 있었는가
- 새 취향이 필요한가, 현재 규칙의 범위만 좁히면 되는가
- 다음 산출물에서 검사할 수 있는가

자기 평가만으로 후보나 점수를 만들지 않는다.

## 회귀와 철회

`요즘 문체가 별로다`, `방금 배운 규칙을 취소해` 같은 신호가 오면 최근 활성화 항목부터 확인한다.

1. `history`에서 해당 시기의 학습·검토 이력을 찾는다.
2. 현재 지시, 예시 문서, 프로젝트 관례와 충돌한 항목을 특정한다.
3. `revert`로 철회한다. Git 기록을 지우는 reset이나 rebase 대신 되돌림 커밋을 남긴다.
4. 검사기를 다시 돌려 기존 공개 규칙과 다른 활성 취향이 깨지지 않았는지 확인한다.
5. `status`에서 후보·활성 항목과 검토 완료 지표를 확인한다.

철회도 로컬에만 남는다. 어떤 이력도 자동으로 외부 저장소에 전송하지 않는다.
